# v0.8.0 — Partial Middle-End availability and transport compatibility

## Middle-End availability

Telego can admit healthy Middle-End links while other slots remain unavailable.
Unavailable DCs use direct fallback. Failed slots recover independently.
Each admitted link must complete its handshake and a matching RPC probe.
Initial construction, handshakes, and probes have bounded deadlines.

A replacement generation must preserve the active generation's ready coverage for each desired DC.
If a candidate loses that coverage, the active generation continues to admit clients.
Existing bindings retain their physical links.

## HTTPS carrier

HTTPS carriers permit four concurrent uplink batches for each lane.
Telego applies batches in sequence and accepts byte-identical retries without duplicate delivery.
The bridge starts another batch only after acknowledgments advance the complete sequence prefix.
Older bridge documents retain serialized requests.

The bridge delivers complete downlink frames before the response body ends.
It advances the cursor after the complete response passes its checks.
After an interrupted response, replay checks prevent duplicate frame delivery and reject changed bytes.
Queued bodies, replay buffers, and temporary application capacity remain bounded.

Carrier selection remains explicit. Existing `websocket` and `websocket-lanes` configurations retain their carriers.
These changes do not establish the cause or resolution of rare mobile WEB stalls.
Controlled carrier tests measure integrity, resource use, and stability on the test route.

## TLS compatibility and diagnostics

FakeTLS accepts ClientHello messages split across multiple TLS records.
The parser bounds the complete handshake and record count.
Probe fallback retains the original wire bytes.
Synthetic ServerHello responses skip GREASE values when they select a cipher.

The new `telego doctor -c /path/to/config.toml` command checks the resolved fallback endpoint.
It uses `splice-host`, `splice-port`, the mask hostname, and the configured PROXY preface.
It checks certificate trust, hostname, and validity.
The optional `--cert-source` flag checks `cert-host` and `cert-port` separately.

Linux also has experimental ServerHello pacing through `server-hello-segment-size`.
Zero, the default, disables this feature.
The value controls TCP payload bytes per paced write. It does not change TCP MSS.
Later bulk traffic retains the negotiated MSS.
An enabled value does not establish a filtering or throughput improvement.
See the [TLS documentation](../tls-fronting.md) for limits and diagnostic scope.

## Toolchain and dependencies

Both Go modules require Go 1.27.3.
The release refresh covers all declared Go dependencies and the Python transfer harness.
Compatible version choices and registry exceptions appear in the [dependency report](../investigations/upstream-reliability-dependencies-2026-10-20.md).
The refresh preserves the local gnet source patches.

## Upgrade

Restart Telego after the binary or container update.
Existing secrets, proxy links, and carrier values remain compatible.
ServerHello pacing stays disabled unless the configuration enables it.
The certificate diagnostic does not change runtime certificate policy.
